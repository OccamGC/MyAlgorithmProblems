# 生成序列中的预算选择 — 补充解法

**Codex（GPT-6）补充解法：排序后的最便宜前缀。** 按[主解法](solution.zh.md)生成序列并先取所有非正数。若扣除它们后预算仍为负，输出零。否则将剩余正数升序排序，从小到大加入，直到下一项超过剩余预算。

同样数量的位置中，选择最小的这些值具有最小总和：任何选择若漏掉较小值而包含较大值，都能通过交换降低或保持费用。因此排序前缀可行时其长度能够达到；下一个前缀不可行时，任何相同或更大数量的正数选择都不可能更便宜。这证明答案正确。

生成与扫描耗时 $O(n)$ ，排序最坏 $O(n\log n)$ ，总空间 $O(n)$ .递推和费用使用 64 位，生成项存为 32 位。此方案有确定的排序时间界，适合需要完整排序结果或规模较小的场合。

这份[程序](alternative.cpp)计算所有正式配方的结果均正确，但完整压力输入的参考测量超过预估时限，不能宣称通过当前完整评测。它保留为备用及交叉验证；同一机器的逐次时间见[性能记录](../../../docs/benchmark-R31.json)。一份排序实现超时不等于证明所有 $O(n\log n)$ 算法都会超时。
