# 性能约束方案（讨论稿 v0.3）

## 推荐方案：题目规模与评测时限分层

**题面层**定义输入规模、结构保证和输出规模。这些条件属于问题本身，跨硬件、语言和编译器保持一致。另给出一个在指定参考环境下测得的**预估时间限制**，供做题者估计程序规模；它不作为所有平台通用的秒数。题面同时注明正式时限的计算规则。原题的旧秒数仅作内部历史记录，不直接认定为新版时限。

**题解层**说明参考算法的时间、空间复杂度，并注明会影响常数的关键实现或输入形状。复杂度属于解法分析，不要求在公开题面中提示目标复杂度。

**评测层**保存可再生成的压力数据、应通过的标准程序和至少一种有代表性的过慢程序（如能找到）。部署到具体 OJ 时，使用目标平台的编译器、选定语言和评测机重新测量，以标准程序的运行时间乘以约定倍率得到正式时限，同时验证过慢程序仍能被区分。评测用程序都以源码交付，不打包可执行文件。

参考环境采用题库级配置编号（例如 `R1`），记录 CPU、操作系统、编译器版本与选项、计时口径等信息；每题只引用编号并填写一个预估秒数。配置变化时新增编号，不悄悄改写旧测量结果。字段见[参考评测环境模板](参考评测环境模板.md)。

每题的参考预估值也按该环境实测的 `T_std` 乘以同一倍率 `k` 计算，以 **0.5 秒为最小单位向上取整**；不可直接沿用原题秒数。目标评测平台若只支持更粗的粒度，再向上取整到可设置值。实测结果与原始测量记录见[评测环境与性能](评测环境与性能.md)。

## 如何校准秒数

对每份程序与压力用例重复测量，采用每例运行时间的中位数来降低偶发噪声；用标准程序的最慢用例得到 `T_std`。`T_good` 是所有应通过程序（包括标准程序）的最慢用例时间。对每份应超时程序取其最慢用例，再在这些程序中取最小值作为 `T_bad`。在同一平台、同一编译配置下，以标准程序为基准确定时限 `L`，并核对以下条件：

```text
L = ceil_to_resolution(k × T_std)
L >= a × T_good
L <= T_bad / b
```

`k` 是对标准程序的倍率，**默认取 `2`，允许逐题根据实测结果调整**；调整值及原因写入单题记录，并在中英题面保持一致。`a` 和 `b` 分别是正确实现的通过余量和与过慢实现的分离余量。可先试 `a = 2`、`b = 1.5`，再按题目表现调整；这与 [ICPC 题目包规范的时间裕量思路](https://icpc.io/problem-package-format/spec/2025-09.html)一致。如果不存在合适的 `L`，应先检查压力数据、程序覆盖和倍率设置，而不是硬填一个秒数。没有过慢程序时，只能得到通过方的下界，不能据此证明某类低效算法会超时。

例：某平台上 `T_std = T_good = 0.8 s`、`T_bad = 5.0 s`，若该题采用 `k = 2.5`，则 `L = 2 s`；它也满足 `a = 2`、`b = 1.5` 给出的 `1.6 s <= L <= 3.33 s`。换平台或语言后重新测量，不沿用这个数字。

## 为什么不单用其他方式

| 方式 | 主要不足 | 建议用途 |
| --- | --- | --- |
| 固定秒数和一台标准机器 | 编译器、运行环境和未来硬件变化会改变结果 | 某个 OJ 的部署配置与历史记录 |
| 只写目标时间复杂度 | 忽略常数、内存访问和输入输出成本，也可能泄露预期解法 | 题解与内部验收说明 |
| 统一的“操作次数”指标 | 不同算法的操作不可直接等价，难以成为通用判题规则 | 少数适合精确定义操作的特定题目 |
| 每题校准正确与过慢实现的间隔 | 需要维护额外程序和压力用例 | 新版题库的默认验收方法 |

## 对文件结构的影响（待确认）

- `tests/plan.json` 增加专门的压力数据组及生成种子。
- `std.cpp` 是一份应通过的实现；若不同正确算法的常数差异显著，可额外保存其他应通过实现。
- 按需加入一份或多份“应超时”源码，并标注其目标复杂度和它应被哪组数据区分。文件名和目录尚待确定。
- 每次部署记录目标平台的操作系统、CPU、编译器与选项、语言运行时、测量方式、结果和最终时限。这份记录属于部署资料，不作为跨平台的题目定义。

## 需要决定

1. 已确定基础取整粒度为 0.5 秒；部署平台仅支持更粗粒度时，最终时限怎样显示和记录仍须随平台确定。
2. 哪些编程语言需要正式支持？每种语言都要单独确认通过裕量，不能只测 C++ 然后推断其他语言的时限。
3. 是否要求每题都有过慢程序？建议在首次试运行中尽量提供，确实不适用或制作成本过高时记录原因。
4. 内存限制是否也改为部署配置，或在题面保留一个与问题有关的明确上限？
