# 评测环境与性能 / Environment and measurements

## 环境与口径

测量平台为 Intel Core Ultra 9 275HX、Windows 11（10.0.26200）、GCC 16.2.0、Python 3.12.14。C++ 编译选项为 `-std=c++17 -O2 -DNDEBUG -Wall -Wextra -Wpedantic` .

每份输入先运行一次生成答案并读取进程峰值工作集，再独立计时五次，取中位数；树形压力构造的确认与校准使用七次，原始记录注明次数。比较两份程序时交替运行顺序。整题取所有用例中最大的中位数，乘以 2，再按 0.5 秒向上取整。计时包含进程启动、读入和输出，不包含数据生成与校验；峰值工作集包括进程运行开销。时间与内存列分别取最大值，可能来自不同用例。

Measurements use the platform and compiler flags above. Each input has one output-generation and peak-memory run followed by five timed runs; targeted tree confirmations and calibration use seven, as recorded in the raw data. Comparisons alternate program order. The limit is twice the largest per-case median, rounded up to a multiple of 0.5 seconds. Timings include startup and I/O; peak working set includes process overhead. Time and memory maxima may come from different inputs. Recalibrate on the target judge.

## 规模与操作次数 / Scale and operation counts

另有护林员四百万节点、庆典计划两百万节点、粉碎者一百万节点的性能实验。这些规模超出题面正式上限，仅用于分析增长趋势，详见[扩大规模的测量](benchmark-P1-scale.json)。随机树、梳形树、长臂树和长链窗口均未形成可用上述时限余量可靠排除另一份程序的差距。理论上多一个对数因子，并不保证在这些输入规模上就有明显耗时差。

Additional experiments use four million vertices for Forest Ranger, two million for Festival Plan and one million for Grinder. These exceed the published limits and serve only to examine scaling; see the [scale measurements](benchmark-P1-scale.json). Random trees, combs, spiders and chain windows do not provide a reliable exclusion gap with the stated timing margin. An extra logarithmic factor need not produce a large runtime gap at these sizes.

实际排序比较次数、分治块大小与线段树查询循环次数见[操作统计](performance-work-P1.json)。它们衡量执行的工作量，不能代替各阶段计时或缓存测量。四题题解分别解释了收益数量与分布、局部深度、虚点扩树和分块粒度对耗时的影响。
